# 门店商学院小程序 · 实施说明 V1

> 代码在 `WeChatProjects/shangxueyuan`，数据底座是飞书多维表格「门店商学院-数据底座」（app_token `AI1qb7KQvalW3OsRAkpcU9VOnqd`）。

## 一、架构

```
店员微信 ──> 微信小程序 ──> 云函数 api（openid 鉴权 + 服务端判分）──> 飞书多维表格
                                   │
                            app_id / app_secret
                            只存在云函数环境变量里
```

为什么中间必须有一层云函数：

- 飞书应用的 `app_secret` 一旦打进小程序包，等于把整套多维表格的读写权限公开；
- 云函数调用外网不需要配置「服务器域名」，方案里「免域名、免备案域名」的结论依然成立；
- 答案不下发前端、超时判卷、切屏计数这些规则必须在服务端执行。

## 三、上线四步

### 1. 开通云开发并填环境 ID

微信开发者工具 → 云开发 → 新建环境（按量计费，7～200 人基本在免费额度内）→ 复制环境 ID，
填到 `config/env.js`：

```js
var CLOUD_ENV_ID = 'prod-xxxxxxxx';
```

填完后小程序不再走演示数据，改为调用云函数。

### 2. 部署云函数

1. 在开发者工具里右键 `cloudfunctions/api` → **上传并部署：云端安装依赖**；
2. 云函数配置里把超时时间调到 **20 秒**（要串几次飞书接口）。

### 3. 配飞书应用凭证

云开发控制台 → 云函数 → `api` → 配置 → 环境变量：

```
FEISHU_APP_ID=cli_xxxxxxxx
FEISHU_APP_SECRET=xxxxxxxxxxxxxxxx
```

飞书侧自建应用需要：

1. 开放平台「权限管理」开通多维表格读权限（`bitable:app` 或「查看、评论、编辑和管理多维表格」），然后**发布版本并让管理员审批**；
2. 打开多维表格「门店商学院-数据底座」→ 右上角「…」→「…更多」→ **添加文档应用** → 选这个应用 → 给 **可管理**（否则会报 403 / 1254302）。

### 4. 自检

```bash
FEISHU_APP_ID=cli_xxx FEISHU_APP_SECRET=xxx node scripts/feishu-smoke.js          # 只读
FEISHU_APP_ID=cli_xxx FEISHU_APP_SECRET=xxx node scripts/feishu-smoke.js --write  # 带写入回环
```

看到 9 张表的记录数、课程解析、写入/更新/删除都 ok，就可以在真机上跑「绑定 → 学习 → 考试」了。

## 四、和方案 V1 的差异（需要你确认）

1. **章节降级为课程级课件**：底座没有「章节」表，课件附件挂在课程上、学习进度也是课程级。
   所以原来的「读完最后一个章节」「按章节记进度」改为：课件页停留 ≥60 秒 + 手动「标记为已学完」，
   服务端再从首次打开时间兜一道 30 秒门槛。以后要章节粒度，得加 `章节` 表并改造学习进度。
2. **申诉没有落库**：底座没有申诉表。成绩页给的是「带解析找店长复核」，后台能查到的是答题明细 + 提交时间 + 切屏标记。要做申诉流，需要加一张 `申诉` 表。
3. **自动得分公式是写死的**：`考试记录.自动得分` 的公式把 10 道标准答案钉死在 `答题1..答题10` 上。判分已经移到云函数，公式只用于展示；**一旦题库换题或超过 10 题，这个公式会显示错误分数**，建议删掉，或改成只看云函数写入的 `得分`。
4. **证书自动颁发**：及格即在「证书颁发」写一条「XX 结业认证 / 初级 / 有效」。
5. **切屏只标记不判作弊**：小程序 `onHide` 计数，交卷时带上；≥3 次写入 `查重状态=疑似重复`，由店长复核。

## 五、试点前还要办的证（与代码无关）

- 小程序备案：免费，1～2 周，**不备案不能发布**；
- 企业微信认证 + 关联小程序 + 工作台可见范围（先只勾试点门店 7 人）；
- 小程序后台配置《隐私保护指引》，勾选「收集姓名、手机号、门店」。

## 六、容量与风险

- 飞书接口有频率限制，当前设计：课程/题库/考试配置读有 15 秒缓存；学习时长 **每 60 秒才上报一次**；交卷一次批量写答题明细，不逐题请求。
- 答题明细会持续增长，目前是取全表后在内存过滤；超过约 2000 行时建议改成服务端 filter 下推。
- 学习进度按「累计分钟 / 标准学时」折算百分比，课件时长不够会停在 99%，完成学习才置 100%。
